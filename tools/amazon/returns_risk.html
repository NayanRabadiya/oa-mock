You are given the repository of a return / risk evaluation service. When a customer asks to return an item, it decides whether to auto-approve the return, send it for manual review, or reject it, and returns the reason codes a support agent sees.

The logic spans several components:

  • category returnability and return-window validation,
  • linked-account aggregation and return history,
  • order-value-based scoring and the risk-score calculation,
  • auto-approve / manual-review / reject decisions and reason mapping.

Issue: support agents report wrong decisions: returns rejected on the last day of their window, customers with an obvious return pattern across linked accounts approved automatically, expensive multi-unit returns scored too low, and high-risk returns sent to review instead of being rejected. 6 integrated test cases fail.

Understand the codebase and the existing logic, run the tests, find why they fail, identify the right component, change the implementation, and run the tests again until they pass. The rules are in README.md.

Note: the acceptance criteria are the predefined tests; more tests run when you submit. The repository may contain issues unrelated to this task.
